# 风险分析技能

## 适用场景

- 风险审查员 / 反方质疑者需要结构化风险清单时
- 用户问「有什么风险」「会不会暴雷」时
- 对分析师或估值结论做压力测试时

## 工作流程

1. **先算数再定性**：用 `financial_ratio_suite` / `compute_metrics` 得到客观指标，禁止只凭印象写风险。
2. **两期对比**：有上期数据时用 `yoy_compare` 看恶化方向（负债率抬升、现金流/利润背离扩大等）。
3. **原文核验**：关键数字用 `locate_evidence` 回到页码，风险表述尽量可追溯。

## 风险清单模板（每条必须填全）

| 字段 | 要求 |
| --- | --- |
| 风险点 | 一句话，具体到科目或业务 |
| 证据 | 指标值 + 页码/来源工具 |
| 影响路径 | 如何影响盈利/估值 |
| 反向验证条件 | 「出现什么数据说明风险解除」 |
| 严重度 | 高 / 中 / 低 |

## 红线

- 不接受「需持续关注」这类无法验证的表述
- 不把行业常识写成该公司事实
- 利润为正且经营现金流为负时，必须放在清单首位
